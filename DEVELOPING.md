# Разработка «Доски истории»

Проект: C# / WPF, `net10.0-windows`, Windows x64. Файл проекта — `HistoryBoard.csproj`. Node.js, база данных, секреты и переменные API не требуются.

## Быстрый запуск

Из корня репозитория в PowerShell 7 (`pwsh`):

```powershell
pwsh -NoProfile -File .\dev.ps1 -Task build -Offline
pwsh -NoProfile -File .\dev.ps1 -Task run -Offline
pwsh -NoProfile -File .\dev.ps1 -Task test -Offline
```

`build` собирает Debug, `run` собирает и открывает редактор, `test` публикует автономную Release-сборку и запускает существующие самопроверки. Результаты тестов и снимки интерфейса находятся в `test-results\local`. Каждую команду выполняйте в отдельном процессе PowerShell, как в примере: скрипты меняют переменные окружения своего процесса.

В этой рабочей папке SDK установлен в `.tools-home\dotnet`, а необходимые пакеты сохранены в `.tools-home\nuget-feed` и `.packages`. Параметр `-Offline` использует локальный источник; для новых зависимостей или другого SDK его потребуется пополнить либо убрать этот параметр. При автономном восстановлении NuGet не получает свежие сведения об уязвимостях из интернета.

На новом компьютере установите PowerShell 7 и .NET SDK 10 для Windows x64 и выполняйте команды без `-Offline`. Скрипт предпочитает локальный SDK, если он есть, иначе использует системный. Windows PowerShell 5 (`powershell.exe`) не подходит: существующие скрипты проекта сохранены в UTF-8 без BOM и содержат кириллицу.

Данные ручного запуска через `dev.ps1` сохраняются в `.tools-home\dev-data`, отдельно от пользовательских уроков в `%LOCALAPPDATA%\HistoryBoard\Data`. Автоматическая проверка обновлений при обычном запуске сохраняется.

## Сборка для распространения

```powershell
pwsh -NoProfile -File .\dev.ps1 -Task release
```

Это существующий `build.ps1`: он обновляет иконку, публикует приложение и кладёт установщик с SHA-256 в `Готовое приложение`. Для номера версии используйте `build.ps1 -Version` в окружении с SDK. Порядок выпуска через GitHub описан в README; CI уже запускает сборку и самопроверки.

## Git и локальные файлы

Исходная ветка — `main`, удалённый репозиторий — `origin`. Перед новой задачей получите изменения и создайте отдельную ветку. SDK, пакеты, сборки, тестовые уроки и результаты исключены существующим `.gitignore`.

Если Git в этом окружении сообщает `schannel: AcquireCredentialsHandle failed`, используйте `git -c http.sslBackend=openssl fetch origin` (аналогично для `pull` и `push`). Проверка сертификатов остаётся включённой.
